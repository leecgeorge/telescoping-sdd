# Changelog

All notable changes to the **telescoping-sdd** plugin — the two-tier methodology of `project-blueprint` (project tier) and `spec-driven-dev` (feature tier). Newest first.

## 2.27.0 — A free fix is free, and the documented pipe escape finally works
**Impact:** the previous release made every fix cost a full review pass. That was right for a pass that was about to end the review and wrong for one that was continuing anyway — and it turned a review that would have converged in one pass into four. A fix is now priced against whether the pass was going to exit at all, so a pass that is already continuing absorbs its medium- and low-severity tidying for free. Separately, the escape sequence the format contract has always told authors to use for a literal pipe now actually works, and a row that still cannot be parsed stops the archive instead of vanishing from the audit record.

**A fix is priced per pass, not per fix.** The cost of fixing something is one additional review pass — but only if the pass was otherwise going to exit. The rule now branches on a single discriminator, and deliberately not the obvious one: *did a high-severity concern land in the blocking set* (fixed, routed downstream, escalated to the user, or halted), **not** *did this pass raise one*. A high-severity concern that was sealed or accepted on the record is non-blocking, so a pass that raised one can still exit — and treating that as a free ride would manufacture the very extra pass this change removes. On a pass already made non-terminal, every medium and low finding worth fixing is fixed at zero marginal cost. On a pass that could exit, each is accepted with a recorded justification instead — or re-graded, which is the only escape valve: wanting to fix a medium finding here is evidence the grading was wrong, and a concern that genuinely must be actioned already meets the high-severity bar. Routing a concern downstream is priced identically to fixing it, because deferring *feels* free — it reads as routing rather than editing — and costs exactly the same pass. Escalation to the user survives at every severity: it records that the reviewer cannot decide alone, which no pricing rule can wish away.

**The documented `\|` escape now works.** The `Latest pass detail` format contract has always instructed authors to escape a literal pipe in a concern or notes cell as `\|`. The archive parser split on *every* pipe, so an escaped cell still produced a phantom cell, the row's cell count disagreed with the header, and the row was warned about and dropped. A dropped row is not cosmetic: it vanishes from the severity counts and the audit trail, and a dropped `User input needed` row silently disables the gate that is supposed to block the archive. Header lines and data rows are now split by one shared rule that honours the escape, so the two can never disagree on cell count. The published advice is corrected in both tiers to describe what the parser actually does — it previously claimed such a row is *silently* dropped, which was false in both halves once this landed.

**An unparseable row now refuses the archive.** Warning and continuing meant a genuinely malformed row was erased from the record by the very pass that cleared the table. The archive now stops, naming the offending line, its actual-versus-expected cell count, and — this is the useful part — *which table it came from* and the consequence that actually applies: an unparsed `Latest pass detail` row is invisible to the escalation gate and to seal and deferral promotion, while an unparsed `Trajectory` row is uncounted, so pass numbering and the convergence signal are computed from an incomplete table. The dry-run check gives the same verdict as a real archive, so the problem surfaces before anything is written. This is a behavioural change for anyone carrying a tolerated malformed row; rows broken by the escape bug self-heal under the parser fix, and the residual population is rows that were already being erased.

**A spec driven by a project plan stops re-deriving the plan.** When a feature is driven by an upstream project plan — it carries a bound feature identifier, or is derived from another repository's plan — its `## Objective` no longer needs to restate the problem, users and goals the plan already fixes at project altitude. The heading stays (it is still a required section) and carries a provenance pointer plus a one-line gloss giving the local "why" without opening the plan. The trigger is strictly upstream-plan-drivenness and nothing else — not how user-facing the feature is, not who its audience is — which deliberately avoids resurrecting a heuristic withdrawn in an earlier release. A standalone feature is not eligible and keeps its full narrative. The drafting agent is told to emit the thin form and not to flag it as a gap in its own self-review, the review panel is told the brevity is sanctioned so it is not raised as an omission, and that sanction is narrow: it licenses brevity only, and a reviewer must still check that the gloss says something the plan does not already say.

**Point rather than restate.** The spec templates are multi-view by construction — success criteria mirror the acceptance criteria, boundaries mirror them, the file list mirrors what they commit to — so every fact has three or four legitimate homes and an incremental edit desyncs the copies it did not touch. Where a fact has an authoritative home, other sites now point at it rather than restating it. The convention is conditional, never absolute: a pointer names a location and a role and never describes what the target says, because a glossed pointer is a restatement smuggled inside it and can be false from the moment it is written. The authoritative home is the most *durable* site, not merely the most complete one. This is a consistency measure and is explicitly not a length reduction — de-duplicating by pointer typically makes a document slightly longer.

**A manually scoped late pass is sanctioned.** On a large artifact's late pass the orchestrator may tell reviewers what changed since the last pass and what is already settled, and let them self-select depth against that scope. That self-selection is the saving; nothing instructs a reviewer how much to read. Evidence may be pre-loaded only if the orchestrator already holds it from having applied the fixes — gathering evidence specially in order to pre-load it moves the verification onto the most expensive context available and forfeits the saving. This sanctions the *scope* a reviewer is pointed at, never the *severity bar* it applies. The section ships with its own obligation test for future editors: a clause that removes work is admissible, a clause that creates an obligation is not — because a mechanized ancestor of this idea was built, measured to *increase* reviewer tool-use, and withdrawn.

**Scope.** One production module (`archive_pass.py`), nine discipline surfaces across both tiers, and four test files. **No validator or content-hash basis changes** — `validate_spec.py` and `content_hash.py` are byte-unchanged, so an artifact already carrying an approval hash needs no re-approval and no cascade fires.

## 2.26.0 — Factual falsity is HIGH, and an edit costs a pass
**Impact:** two ways an unreviewed or wrong statement could reach an approved artifact are now closed. A panel reviewer finally has a rule to grade a statement that is simply *false about the codebase*, and the pass that fixes something is no longer allowed to also be the pass that ends the review.

**A statement that is factually false is now `[HIGH]`.** The shared severity definition — the three-line rubric dispatched verbatim into every reviewer's prompt — listed only three ways an artifact can be wrong as written: it contradicts itself, it regresses a settled decision, or it commits to something unimplementable. A claim that a helper exists when it does not, that a file lives where it no longer does, or that a dependency has a property it lacks tripped none of them, so it graded `[MED]` ("correct as written but could be better") — which it is not. Meanwhile every drafting agent was already held to a factual-accuracy standard in its own self-review. The plugin enforced accuracy on authors and gave reviewers no clause to enforce it back. A fourth criterion now covers it, inside the existing `[HIGH]` sentence; the `[MED]` and `[LOW]` bullets are untouched.

**An edit now costs a pass.** Previously the pass that exited the review loop could still *fix* things on its way out — which meant an edit reached an approved artifact after the last reviewer had read it, contradicting the loop's own stated reason for blocking on fixes ("an edit was made and nobody has reviewed it"). The fix is to price the edit rather than forbid it. The reviewer disposes every concern on its merits first, without regard to whether the pass will exit; terminality is then evaluated over the rows just written, in order: an unresolved high-severity concern continues the loop; otherwise any concern disposed `Addressed` (i.e. fixed) continues it, and the next pass exists to review those edits; otherwise the loop exits. So fixing is always permitted and exiting is always permitted — just never on the same pass.

Because a fix now costs a pass, the doctrine also gives a per-concern test for whether a medium- or low-severity finding is worth one: fix it if it touches an acceptance criterion, an interface or named dependency, a statement a later phase will build on as fact, or a security or privacy surface — otherwise accept it on the record. When in doubt, fix it. There is deliberately no trivial-edit exception, because the rule never forbids a fix; it only prices it.

Supporting changes keep the rule coherent everywhere it is read: `Accepted as risk` now covers reviewer-judged acceptance as well as user-confirmed acceptance, and must say which it was, so a later reader cannot infer a sign-off that never happened; acceptance is deliberately *not* routed through `Deferred`, which feeds a separate convergence trigger; and the rule is explicitly bound where the review can exit by another door — the audit pass that follows a narrowed-scope review, the five-pass cap, single-pass lightweight mode, and mechanically-skipped passes. The cap and lightweight mode are not convergence exits, so the rule does not apply to them; a skipped pass can never be the pass a loop exits on.

**The exit test now names its property, not its mechanism.** It previously named `Defense:` — the on-disk marker — rather than what that marker is for. It now states the property first (a pass may exit only when every high-severity concern it leaves standing carries an on-disk, reviewer-visible justification) and presents `Defense:` as that property's implementation, cross-referenced to the disposition set in `archive_pass.py` so it can be re-derived from the code. This is a wording change with no behavioural effect of its own: the committed formulation survives verbatim inside the new text, and every existing convergence test passes unmodified.

**Scope.** Prose and tests only. Both `panel-review.md` copies and their convergence and modes references, both `SKILL.md` files, both walkthrough references, and the test suite. **No script, validator, or content-hash basis changes** — `archive_pass.py` is untouched, so an artifact already carrying an approval hash needs no re-approval and no cascade fires.

## 2.25.0 — Severity definition + unresolved-HIGH exit predicate
**Impact:** a panel pass whose every HIGH was deliberately sealed now **exits** instead of buying one more three-panelist pass. That pass was near-zero-yield by construction: step 1 already instructs panelists not to re-raise a sealed item without new substantive evidence, so the confirming pass could not audit the seal it was convened for.

Two changes, one cause. **`[HIGH]` had no definition anywhere the panel could see it.** The only artifact-shaped definition sat in the *rationale* of step 8 — the step about exiting, not about raising — and was never dispatched to a panelist. Four of the ten personas carried their own `Severity Classification` blocks, they disagreed with each other, six carried none, and three of the four graded on running-system harm (data loss, privilege escalation, injection) over documents that have no runtime.
- **One shared severity definition, dispatched verbatim.** `## The Loop` step 1 of both `panel-review.md` copies now carries the axis — `[HIGH]` = the artifact is **wrong as written** and shipping it downstream produces rework; *"could be better"* is `[MED]` — plus the reminder that a spec is a document, not a running system.
- **Review scope, stated with it.** The `## Panel Review` section is the loop's own audit record and is not itself under review; defects there are Synthesizer Self-Check territory. Two narrative fields (`Routed because:`, `Defense:`) are carved out and capped at `[MED]`, with a decidable flag-vs-audit test — and one uncapped exception for instruction-like prose aimed at the next reader.
- **Four persona rubrics become domain lenses** on that shared axis, each opening with its own artifact scenario and closing with one identical sentence. `security-reviewer`'s orphan `Critical` tier is folded into `[HIGH]`; the six rubric-less personas are untouched.
- **The exit test reads *unresolved* HIGHs.** Exit when a pass returns no HIGH concerns other than those dismissed with a recorded `Defense:` — i.e. disposed `Sealed` / `Accepted as risk`. The non-blocking set is *exactly* the dispositions `archive_pass.py` already requires a `Defense:` for, so a future editor can re-derive it from the code. `Addressed` still blocks — an edit was made and nobody reviewed it — and `Deferred` still blocks, because it feeds the strict-bar deferral-rate trigger and moving it would silently move a second predicate.
- **A sealed exit is stamped distinctly:** `converged (0 unresolved HIGH); sealed=<N>` beside the unchanged `converged (0 HIGH)`. The `### Trajectory` **HIGHs** column keeps recording HIGHs *raised*, so a converged row may show a non-zero count; a new troubleshooting entry catches the operator who reads that as a bug. The approval gate discloses the seal count before asking for approval.

**Hand-off to a future approval-gate reader.** `sealed=<N>` is a stable machine token — the grammar `sealed=(\d+)` is a published contract — but emitting it **licenses observation, not enforcement**. Gating approval on its value would re-open the seal-justification question this design deliberately leaves to the `Defense:` requirement. A gate reading the stamp must also **read the whole Notes cell**: a `converged` row may legitimately carry halt-vote text alongside the stamp, and neither half invalidates the other.

Scope: both `panel-review.md` copies, both `panel-review-convergence.md`, both `SKILL.md`, both `examples.md`, `strict-bar-prompts.md`, `troubleshooting.md`, four agent bodies, `archive_pass.py`, and a new `test_severity_and_exit_predicate.py`. Also bundled: four script comments that referenced an author-side planning document by name are reworded to stand on their own — comment-only, no behaviour change. The restatement set was produced by a derived both-polarity sweep, not a hand list — it found roughly twice the sites the spec's seed list named.

## 2.24.1 — Panelist manifest: HIGH count only (drop the unconsumed MED/LOW tallies)
Subtractive follow-up to 2.24.0's severity census. The MED/LOW integers had no consumer — step 2's presence check reads only the HIGH count — and proved unreliable: a panelist declared `7 MED` over a findings file holding 8. The HIGH count survives because a panelist derives it from the anchors it has just enumerated, so it is self-consistent and checkable without reading any file. `counts: 0 HIGH` with `anchors: (none)` remains the compliant manifest for a quiet pass, so 2.24.0's actual fix is untouched. Both `panel-review.md` copies plus the ten panelist `## Output Format` headers; prose only — no script, validator, or content-hash change.

## 2.24.0 — Opus-5 prompt alignment (length, cadence, task scope) + panel output-contract fixes
**Impact:** drafted designs come out roughly a third shorter — −27.6% to −37.5% across three dogfooded features — at **identical specification coverage** (zero acceptance criteria dropped across 201 blind assessments of six drafts), so the gain is *cost* rather than quality: less to read at every review gate and less context carried downstream.

Aligns the plugin's prompt surfaces with Anthropic's *Prompting Claude Opus 5* guidance. Seven of the workflow's actors now run on Opus 5 — the orchestrator/synthesizer (session model) plus the six drafting analysts (`model: opus`) — and the guidance names several behavioural shifts the prompts carried no counter-instruction for. This release addresses the three that are pure gaps: **files written to disk run longer**, **user-facing responses and agentic narration run longer**, and **task scope expands unasked**. No script, validator, WARN, content-hash, or approval-semantics change, and no test asserted any string touched; one bounded doctrine change widens what the Phase-4 discovery triage catches.
- **Length calibration on all six drafters.** Each analyst's `### Writing & Documentation` section gains a **Match length to substance** bullet — cover what the artifact needs and stop; cite what the upstream artifact already commits instead of restating it; no prose that repeats a table beside it; no summary section that recaps the document; *a section that is complete in three lines is complete*. Only the "do not restate…" clause varies by artifact (`PLAN.md` framing for the feature spec, `spec.md` acceptance criteria for the design, `design.md` rationale for tasks, the problem statement for scope, `SCOPE.md` goals for architecture, `ARCHITECTURE.md` components for the plan). On the two spec-tier drafters it **replaces** the older "readable in a few minutes" bullet rather than joining it — two length instructions with different metrics is worse than one. The other four (`feature-architecture-analyst`, `feature-task-analyst`, `project-architecture-analyst`, `project-plan-analyst`) had no calibration at all, i.e. it was present only on the two *shortest* artifacts and absent on the four that actually grow.
- **A counterweight in the inlined self-review, so the ratchet stops undoing it.** Each drafter's self-review `**Gaps**` line is a completeness ratchet that fires after drafting, up to 5 times, and only ever pushes toward more — a drafting-time length bullet with nothing opposing it is decorative. Each of the six now ends with *"Substantive means specific, not long — a section that says the one thing it has to say is done."* Mirrored into `agent-references/agent-self-review-instructions.md` § *3. Gaps* in that file's fuller idiom ("Gaps are missing *content*, not missing *words*"), per the keep-the-inlined-copies-in-sync rule.
- **A `## Communication` section in both `SKILL.md` bodies.** The orchestrator is the Opus-5 actor with the most speaking parts — the skills mandate roughly ten distinct user-facing surfaces (tier announce, pass summary, reset offer, pre-flight contract, halt prompt, strict-bar ask, 5-pass cap gate, exposure triage, prefix-rename offer, stack announcement) and nothing anywhere shaped their cadence or length, while a multi-pass panel loop is exactly the agentic session where Opus 5 narrates most readily. One short block, byte-identical across both tiers, names the mandated surfaces as *the* communication budget, asks for outcome-first ordering when a pass or phase finishes, and limits self-correction narration to errors that change the user's decision. It carries an explicit **floor** — *brevity never means dropping a mandated surface or omitting what it requires* — so a brevity instruction cannot be satisfied by compressing away a gate prompt, a disclosure, or a tier announce; every surface still says everything it owes, it just stops there. Placed immediately before `## See also` in each file rather than near the top, per the guidance's own long-system-prompt pattern (*"pair the instruction with a short reminder near the end of the prompt"*) — both bodies are well past that threshold at 4,848 and 2,499 words before any reference loads.
- **Task-scope boundaries for the two Opus-5 actors that had none.** The synthesizer was already guarded (the Cap-pressure caveat in both `panel-review.md` copies); the six drafters and Phase 4 were not. Each analyst's `## How You Work` gains a **Draft what was asked and nothing beyond it** paragraph — scope comes from the request and any upstream artifact, a suspected omission is raised as `[TBD — needs input]` or an open question rather than written in, and *a template field you have no grounded content for is a question for the user, not an invitation to invent one* (which is where the pressure actually sits: the self-review's "every template field filled" ratchet). It sits directly after the existing format-scope paragraph, extending the same rule from document *format* to document *content*, rather than in the style section.
- **Phase 4: the discovery triage now catches additive scope, not just contradictory scope.** `### Mid-implementation discovery` was already the right machinery — five-criterion major/minor triage, delegated-backport rail, `## Implementation Deviations` ledger — but its entry condition was *deviation from the approved spec/design*. Work nobody asked for contradicts nothing (every acceptance criterion is still satisfied), so it never reached the triage at all. The trigger now also fires on *"find yourself doing work no task asks for."* Crucially, such work is **minor by default** — the `"When in doubt → major"` rule explicitly does **not** apply to it, so it is logged and the run continues, escalating to a halt only when it independently trips one of the five criteria (most often (iv), doing work a not-yet-done task owns). That preserves the no-per-task-gate autonomy that makes Phase 4 work: the goal is an auditable record of what was done beyond the task, not a stop-and-ask loop. Step 3 states the matching boundary — *satisfy the acceptance criteria completely, including the refactor of the code this task touches, and stop there* — phrased as a boundary rather than a thoroughness dial, since Phase 4 already stacks the test-first MUST, the full-suite run, and the R5 completion gate all pushing the other way.
- **Panelist output contract reconciled with the dispatch (adjacent to the Opus-5 work, found during it).** Since v2.22.0 the dispatch has required each panelist to **Write** its findings to `.sdd/panel-findings/…` and **return only a manifest** — but all ten panelist bodies still prescribed in-thread prose (*"Structure your response as: Overall Assessment… Positive Observations… Summary"*), and none mentioned the findings file, the manifest, or the bracketed severity vocabulary at all. The agent body is a system prompt and the dispatch is a user turn, so the **stronger** channel was carrying the wrong instruction and the inflow reduction depended on the weaker one winning on every call. Each `## Output Format` now opens by naming both channels — what you *return* (manifest: path + one anchor per `[HIGH]`, nothing else) versus what you *Write to disk* (the two-section findings file) — and re-aims the persona structure at the file's `## Assessment (human)` block specifically, so it cannot be read as governing the `## Machine findings` list, whose line format the dispatch owns. The persona bullets themselves are unchanged in all ten. `security-reviewer` and `devils-advocate`, the two that define bold-word severities, now carry the on-disk tag beside each label (`**Medium** (write as `[MED]`)`), since `Medium` is not `MED`.
- **A backstop for a panelist that ignores the contract anyway.** Reconciling the bodies lowers the odds of a prose return; it does not detect one. Nothing did: the step-2 reconcile iterates the manifests' `[HIGH]` anchors, so a panelist supplying **no** manifest makes it pass vacuously; the fallback ladder only tests properties of the condenser's returned table; `panel-condenser` has no missing-file handling; and the cruft sweep treats an absent findings subtree as the normal state by design. The failure would have cost the exact context inflow v2.22.0 removed, silently and with no record of the degraded path. Both `panel-review.md` copies now open `## The Loop` step 2 with a **manifest-presence check** — confirm each panelist returned a path that exists on disk plus its anchors, and on failure dispose from the prose you were handed and disclose the degraded mode in the pass summary. Same fall-back-then-disclose idiom the file already uses everywhere else; no new vocabulary and no new machinery.
- **A severity census in the panelist manifest — the contract had no compliant form for a zero-HIGH pass.** Found by dogfooding the change above: the manifest was specified as *"the findings-file path plus one anchor per `[HIGH]` … and nothing else"*, so a panelist that raised **no** HIGH could comply only by returning a bare path — conveying nothing about a review that had found substantial MED-level material. An observed panelist in that position leaked four MED concerns inline instead, violating both the dispatch and its own agent body. The manifest now carries a one-line **severity census** (`counts: <H> HIGH / <M> MED / <L> LOW`), and both `panel-review.md` copies state that a zero-HIGH pass still returns the path and the census with `anchors: (none)` — so a quiet pass always has something true and compliant to report. The ten panelist `## Output Format` headers say the same in the same words (*"if you raised no HIGH, the census IS your report"*). **Step 2's manifest-presence check now keys on the census rather than on anchors**, because anchors cannot carry it: a zero-HIGH pass and a prose-returning panelist both supply none, so on anchors alone the check passes vacuously and the two are indistinguishable — which is the same hole the presence check was added to close, seen from the other side. Verified by re-running the failing case: the same panelist on the same artifact reproduced the zero-HIGH condition and returned a clean census with no inline prose, and both test arms' declared counts matched their findings files exactly. Prose only — no script, validator, or content-hash interaction (panel findings sit outside every hash basis and the manifest is in-thread, never written to disk).
- **Not a retry of the reverted spec-verbosity work** (which briefly held this same version number before being rolled back). That failure was located precisely: subtraction at *drafting* time was safe; subtraction at *per-pass disposition* time produced every regression. This change fires only at the drafting actor already cleared as safe, and it is calibration (write the right length) rather than subtraction (cut what exists) — so there is nothing to over-apply against existing text and no anti-rubber-stamp guard to pay for. Section *presence* checks in both validators are unaffected: a short section cannot fail validation.

## 2.23.0 — Active reset-at-gate offer (RESET-CHECKPOINT advisory + passive→active doctrine)
Turns the passive Family-1 "you may reset at a gate" guidance into an **active, gate-triggered offer** the orchestrator makes at every approval gate, backed by a machine-readable advisory that makes `/clear` a deterministic resume recipe. Behavior-, approval-semantics-, and content-hash-preserving throughout (the advisory is decoration emitted *after* the load-bearing stamp/gate returns; it writes no file and feeds no hash). Dogfooded end-to-end through `spec-driven-dev` (Specify → Design → Tasks → Implement, test-first).
- **`RESET-CHECKPOINT:` stdout advisory from both validators.** A new shared leaf `telescoping-sdd/scripts/reset_checkpoint.py` owns a six-key `(tier, gate) → (next-step, [re-read paths])` table plus a pure `build_reset_checkpoint_advisory` and a guarded `emit_reset_checkpoint` (mirrors the `STRICT-BAR-SIGNAL:` builder-prints-caller precedent and `run_state.safe_print`'s `except BaseException` swallow). Both validators emit a one-line advisory after a successful phase-gate `--approve` — and `validate_spec.py` after a passing `--completion-gate` — naming the just-approved gate, the next step, and the exact files to re-read on resume (skill-qualified paths). The SDD completion gate and the terminal blueprint `plan` gate carry "highest-value reset point" framing; the completion variant is deliberately list-free. Emission is gated on a real gate crossing only (never on a refused approve, a `--task-tick` re-stamp, or a failed/blocking gate). The leaf imports only stdlib (acyclic leaf discipline — never a validator).
- **Passive→active doctrine upgrade across four files, parity-guarded.** Both `workflow-overview.md` "Context Management — Resetting at Gates" sections and both `SKILL.md` reset-summary paragraphs are recast from "opt-in and advisory — never automatic, never forced" to "the orchestrator **offers a context reset at each approval gate**," adding `/clear`-vs-`/compact` guidance (`/clear` reloads verbatim from disk; `/compact` keeps only a lossy summary), a gate-triggered-always escalation rule (tone scales with observable proxies; a live context-% gauge is never the trigger), and a read-and-act-on-the-`RESET-CHECKPOINT`-advisory instruction. A new `test_workflow_overview_parity.py` asserts the five named-presence anchors in both `workflow-overview.md` copies, the active anchor present + passive string absent in both `SKILL.md` paragraphs, and shared-prose equality (each tier's specifics confined to one excisable per-tier fragment, compared modulo the `validate_spec.py`→`validate_blueprint.py` / `<spec-dir>`→`blueprint/` swap).
- **Isolation + neutrality guards.** The emitter swallows every `BaseException` and always returns `None`, so an advisory-construction failure can never change an approval's or completion-gate's exit code (R9); on failure it writes a type-name-only `RESET-CHECKPOINT-DEBUG:` trace to **stderr** (never the stdout advisory the orchestrator reads). A dangling-reference guard asserts every re-read path resolves on disk; a `next_step_label` drift guard imports the validators' phase constants and asserts each label matches the canonical successor; and in-process stub-vs-live equivalence tests (with emit-reached canaries) prove byte-identical stamped hashes, `tasks.md` bytes, and per-CFC baselines with the emitter live vs. stubbed at every emission site.

## 2.22.0 — Panel-review context-inflow reduction (off-thread condenser + terser panelist contract + delegated consistency reads)
Cuts what enters the MAIN orchestrator context window during a panel-review loop, so long multi-pass loops stay well clear of the compaction cliff. Behavior-, approval-semantics-, and content-hash-preserving throughout (same disposition vocabulary, same on-disk `## Panel Review` format, same `archive_pass.py` contract; both `panel-review.md` copies change in lockstep). Dogfooded end-to-end through `spec-driven-dev` (Specify → Design → Tasks → Implement, test-first).
- **Findings-to-disk panelist contract + off-thread `panel-condenser`.** Panelists now **Write** their full findings to `.sdd/panel-findings/<findings_scope>/<artifact-stem>-p<PASS>-<panelist>.md` and **return only a manifest** (path + one identity anchor per `[HIGH]` — id, ≤120-char single-line gist, optional scope-tag hint), so raw panel prose and every MED/LOW body stay on disk instead of entering the main thread. A new thin `telescoping-sdd:panel-condenser` agent (pinned Sonnet/high) reads the findings files off-thread and returns **one 8-column compact disposition-*proposal* table**; the orchestrator reconciles it **by identity, per anchor** (present + HIGH-severity + source-attributed + gist-consistent, merged rows checked per contributing anchor) and falls back to reading the raw findings — disclosing the degraded mode in a new **`## Pass summary surface`** — on any syntactic / structural / fidelity failure. The condenser *proposes*; the orchestrator still disposes, runs the Self-Check, confirms `[upstream]` semantically, and owns every gate.
- **Interchange-shape validators (`compact_table.py`).** A new pure leaf `telescoping-sdd/scripts/compact_table.py` deterministically validates the *shape* of the two off-thread payloads — `validate_compact_table(text, *, phase)` (the AD8 bucket-A grammar over the 8-column table, with a phase-conditional `SCOPE` rule) and `validate_discrepancy_list(items)` (the consistency-check discrepancy schema). It single-sources the disposition vocabulary **and** the `→ target` base-extraction split by importing one behavior-preservingly-extracted `is_known_disposition` helper from `archive_pass` (one-way — `archive_pass` never imports it, so its CLI/parsing contract is untouched). The `archive_pass.py` touch is exactly that additive helper pair (`disposition_base` / `is_known_disposition`), with all eight in-module base-extraction sites routed through it so there is literally one copy of the split rule.

## 2.17.0 — Best-effort .sdd/ cruft cleanup
Both validators now tidy up after themselves: at process exit, `validate_spec.py` and `validate_blueprint.py` sweep orphaned `.sdd/*.tmp` atomic-write temps and reclaim the `pending-review.lock` backing file, so a `.sdd/` left behind by an interrupted run no longer accumulates cruft. Best-effort and never load-bearing — cleanup never raises, never changes a run's exit code, and never touches the intentional `architecture.json` / `pending-review.json` markers. Shared-tier change (new `sweep_sdd_cruft` in `pending_review.py`, re-exported through `blueprint_common.py`); built via the spec-driven-dev workflow (dogfooded).
